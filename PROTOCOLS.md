**Adoption columns** are as of 16 Oct 2026, except the PAP, ANS, Web Bot Auth and ID-JAG rows, updated 19 Nov 2026. The adoption metrics and traction charts further down were all refreshed on 19 Nov 2026. Stars and last-push dates come from the GitHub API. Adopter lists and usage figures come from search results, mostly vendor announcements and secondary blogs, and none were checked against primary sources. A named partner is not a deployment: read "design partner" and "launch partner" as intent, not production use.

**Rating basis:** *Spec* means the specification was read. *Secondary* means rated from announcements, blog posts or press. Protocols whose ratings are provisional would render with dashed chips; none are at present.

- **GitHub topics (repos tagged, 19 Nov):** `model-context-protocol` 46,167; `x402` 4,648; `a2a-protocol` 645; `erc-8004` 415; `l402` 136; `universal-commerce-protocol` 69; `web-bot-auth` 50; `agentic-commerce-protocol` 28; `agent-payments-protocol` 20; `agntcy` 10. Topic counts are noisy and include unrelated and spam repos.

**Read with care**
- Download counts include CI, mirrors and bots. Treat them as relative reach, not users. A2A and MCP counts are inflated by transitive installs from agent frameworks.
- Stars measure attention more than use. The x401 and PAP repos are months or weeks old.
- The MPP and L402 rows cover two repos each because the specification and the reference code live apart.
- `coinbase/x402` is a fork of `x402-foundation/x402`. The canonical repo is the foundation's.
- Packages were matched to protocols by the repository URL in their registry metadata. `pympp` and `pytempo` are published by Tempo, `agentic-commerce-protocol` by Svix and `l402` by Fewsats, and I did not verify that these publishers are authorised by the protocol owners. The `ap2` package on PyPI belongs to an unrelated project and is not counted.
- For Web Bot Auth the most downloaded official npm package is now `http-message-sig`, the HTTP message signatures library in Cloudflare's repository, not `web-bot-auth` itself. The npm history chart still plots `web-bot-auth`.

### Gaps marked on the charts

- **No data is marked, not hidden.** Dashed boxes and panels show where a protocol has nothing to plot, with the reason.
- **No repository or package yet.** Dashed shading marks weeks before a repository existed (commits chart) or before a package had downloads (all-registries chart), so a flat line means no activity rather than no project.
- **Counting choices.** Commits use the default branch only. Downloads cover npm, PyPI and crates.io. Maven, NuGet, Go modules and container pulls are not measured, and downloads include CI and mirrors. A repository that implements several protocols (`solana-foundation/pay`, the NVIDIA retail blueprint) is counted under each and marked in the box.
- **Publishers.** Third-party packages name their publisher in the box. I did not verify whether any publisher is authorised by the protocol's owner.
- **Star history over time** is not shown. GitHub's stargazer endpoints returned nothing in this environment, so stars are a snapshot.

## Notes

- **PAP and Poppy are the same protocol.** Poppy is the nickname; PAP is the formal name. Meta's Muse agent was the live-demo agent at Sierra Summit (6 Oct 2026). It is not a separate protocol.
- **PAP authorship.** The only authorship statement found is Sierra's announcement post, which credits Bret Taylor and Clay Bavor. The spec, site and repo name no authors. On 16 Oct the repo's one visible committer was Arya Asemanfar; by 19 Nov there were three, and the GitHub organisation still has no public members. Sierra's 1.0 post adds that Shopify co-authored the UCP extension.
- **PAP as read from the spec (1.0, 19 Nov 2026).** Version 1.0 was published on 14 Nov 2026, so PAP is no longer rated from a draft. The identity model is unchanged in kind: Session JWTs are now signed by per-user delegated keys vouched for by the `jwks_uri` keys, and a Web Bot Auth operator signature is recommended. Approvals in the Operations extension are unsigned, and signed approvals and mandates are roadmap items. Payments go through the UCP extension. The map's ratings are unchanged. What follows was read from draft 0.1 and still holds unless [research/pap.md](./research/pap.md) says otherwise.
- **PAP as read from draft 0.1 (16 Oct).** The agent is identified by an HTTPS `client_id` pointing at a metadata document with a `jwks_uri` (the OAuth Client ID Metadata Document draft that MCP also uses). Session tokens are DPoP-bound (RFC 9449) with per-request proofs (`jti`, `htm`, `htu`, `iat`, `ath`, optional server nonce); Bearer tokens are allowed only on MCP APIs. Sign-in is OAuth with an account token (refresh token) revocable at an RFC 7009 endpoint. Conversations carry a `sender` field saying whether a human or an AI wrote each message. It defines no credential or DID-based agent identity, and no payment (payments are named as a possible extension).
- **x401 authorship.** Proof is the steward and the repo owner. [`proof/x401`](https://github.com/proof/x401) has Apache-2.0 licence and its CODEOWNERS is the Proof product team. Press coverage names Circle, OpenAI, Okta and Google as contributors; the spec lists Circle as co-editor and OpenAI and Okta as reviewers, and does not list Google. Proof has said it will submit x401 to the FIDO Alliance. That is Proof's claim and the spec names no standards body.
- **x401 proves attributes of a credential holder, not the agent.** The result is bound to the verifier, and agent binding (Web Bot Auth, mTLS, DPoP, SPIFFE) is optional and left to deployments. Delegation, payment sequencing with x402, AP2, ACP and UCP, and when agent binding becomes mandatory are all listed as open questions in the spec. Proof's launch post describes a user-signed spend mandate. The spec does not define one, so the map does not rate x401 on spend limits and rates human-to-agent authority as partial.
- **Not read in full.** For x401, the design goals, binding, agent identification, security and open-questions sections and the changelog were read, not all 1,685 lines. For PAP 1.0, sections 1, 4.1, 5.2 to 5.3, 8.1 and 10, the changelog and Operations 8.1 were read, not the web browsing, API and conversation detail.
- **Amex Intent Intelligence was first named in April 2026** as one of five services in the ACE Developer Kit; the 13 Oct 2026 release made the technical framework (a four-stage flow: create and confirm intent, establish proof of intent, secure the payment credential, apply it to the purchase) public for the first time. No specification document, GitHub repository or SDK was found, so it is rated entirely from press coverage (Digital Transactions, Digital Commerce 360 and others), not a primary source.
- **Unchecked links:** the datatracker, x402.org, modelcontextprotocol.io and docs.cheqd.io links were written from the usual URL patterns and not opened. Check them before relying on them.
- **Source repo:** the map and its history come from [`cheqd/agent-toolkit`](https://github.com/cheqd/agent-toolkit/tree/main/docs/research/tools/capability-map). Rows marked "not recorded" were not captured in that repo's landscape notes.
